# Web 会話ログ分析

更新日: 2026-04-05

## 対象
- ElevenLabs に記録された直近 5 件の `react_sdk` / `status=done` の Web 会話
- 対象時刻: 2026-04-05 00:30 から 13:12 JST

## 前提
- `docs/latency-report.md` の自動蓄積はまだ空で、過去会話の connect_ms / analysis_ms は残っていなかった
- そのため、この分析では ElevenLabs transcript の `time_in_call_secs` を使い、`ユーザー発話の後に次の agent 発話が出るまで` を実効応答時間の代理指標として扱う
- これは厳密なネットワーク遅延ではなく、ASR / LLM / TTS / turn detection をまとめた体感テンポに近い数値

## 全体サマリー
- 対象会話数: 5
- 成功: 1
- 失敗: 4
- 成功率: 20%
- 成功会話の通話時間: 184 秒
- 失敗会話の平均通話時間: 21.8 秒
- 成功会話の初回ユーザー応答まで: 10 秒
- 失敗会話の初回ユーザー応答まで平均: 13.3 秒
- 成功会話の agent 応答時間:
  - 平均: 8.1 秒
  - 中央値: 5 秒
  - 最大: 23 秒
- 失敗会話の agent 応答時間:
  - 平均: 2.3 秒
  - 最大: 3 秒

## 解釈
- 失敗会話はほぼすべて、ユーザーの無言、短い相づち、接続確認だけで終了している
- そのため、失敗会話の `agent 応答時間 2-3 秒` はシステムが速いというより、会話が深く進んでいない結果
- 成功会話では中央値 5 秒で、通常の問い合わせ返答としては大きく破綻していない
- ただし平均が 8.1 秒まで上がっているのは、長い症状説明の要約と、複数候補日の整理を含むターンで 15 秒、23 秒の間が発生しているため

- 5 秒前後で返せているターン:

- 15 秒かかったターン:
  - 症状説明のあとに、痛みへの共感と予約候補日の質問を返した箇所
  - 長い自由発話を要約して返しており、ここは改善余地あり
- 23 秒かかったターン:
  - 候補日時の言い直しと「休みとかありますか？」の複合質問への応答
  - FAQ を prompt に追加したので、次回以降はここが短くなるかを見る価値がある

## 現時点のボトルネック
- 成功率の低さはシステム遅延より、会話開始直後のユーザー無言や音声確認失敗の影響が大きい
- 成功会話では、単純ターンは 5 秒前後で返せている
- 長いターンは、複数情報を一度に受けた時と、FAQ を含む複合質問の時に出やすい

## 次に見るべき指標
- FAQ を prompt に追加した後の `休診日` `診療時間` `アクセス` 質問ターンの短縮有無
- 成功会話 3 件以上での中央値比較
- Web 側の自動蓄積 `connect_ms` `first_agent_response_ms` `analysis_ms`
- phone 会話が溜まった後の Web / 電話比較
