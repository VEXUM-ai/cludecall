# Slack通知と急患 live 引き継ぎの実装方針

最終更新: 2026-04-10

## 1. 方針
- 通常受付は、通話後にシステムが Apotool へそのまま登録し、その結果を Slack で通知する。
- 人の確認は「投入前」ではなく「投入後の確認」に寄せる。
- 急患や人対応が必要な電話は、通話中にそのまま人へ転送する。

## 2. 現状との違い
- これまでの実装は review 承認を前提にしていたが、今後は `direct_auto` を主経路に寄せる。
- Slack は現場の確認用通知として使う。
- 電話番号精度の改善は当面扱わない。

## 3. 実装項目
- Slack incoming webhook 送信モジュールを追加する。
- 予約成功、予約失敗、急患転送の通知 payload 型を追加する。
- `SLACK_WEBHOOK_URL` と `SLACK_CHANNEL_LABEL` を env から読む。
- webhook 未設定時は処理を止めず、通知だけスキップする。
- 予約投入後の結果を Slack に流す。
- 急患は ElevenLabs の live transfer を使い、必要なら固定番号へそのままつなぐ。

## 4. 受け入れ条件
- 通常受付で Apotool 登録後に Slack 通知が飛ぶ。
- Slack 未設定でも予約処理は止まらない。
- 急患では live 転送が優先され、通常の自動予約に進まない。
- 予約成功 / 失敗 / 転送の 3 パターンが区別できる。
